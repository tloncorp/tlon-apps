# Native conversation READ registration, version 1

This production provider supplies actual mounted text/image points to the RN ScrollView's single-writer READ lease. It does not scroll, synthesize native observations, use fixture markers, or make a presentation claim.

## Atomic metadata and hosting

`ScrollReadScopeContainer` and `ScrollReadItemContainer` each accept one `descriptor` JSON string. Scope: `{version:1,scope,visit,intent,phase,dataRevision,rows:[{key,revision}]}`, where phase is `read`, `follow`, `target`, or `inactive`. Rows are the current authoritative loaded order. Row item: `{version:1,scope,visit,key,revision,kind:'row',blocks:[{id,kind,revision,assetKey?}],unresolvedBlockIds?:string[]}`. Inner item: `{version:1,scope,visit,key,rowRevision,blockId,revision,kind:'text'|'media',assetKey?,mediaReady?}`. IDs and revisions are nonempty strings. Media requires an assetKey; readiness must correspond to that exact current asset's successful native image load, reset on replacement. These are metadata declarations, not geometry.

Carriers replace equivalent existing Views with preserved layout/accessibility props. They must not introduce a UIView inside Text or change text shaping. A scope may instead be a zero-size, noninteractive carrier inside existing list content. Each inner host must enclose exactly one actual Paragraph or UIImageView; descendants stop at nested registered carriers. Multiple candidates are unavailable. Registry lookup follows actual ancestors to the nearest RN ScrollView, never a global view/tag scan. Scope and registered row/block revision must agree. Logical block lineage must survive edits; array index alone is not a lineage. Old IDs whose split/merge/repeated-text lineage is ambiguous remain in unresolvedBlockIds, which is disjoint from current blocks. Such IDs are unavailable, never falsely removed. Row revision is the loaded membership generation, stable through independent live content changes; remove/reinsert uses a fresh generation. Block revisions describe actual rendered content.

## Accepted behavior, declared before controls

1. Scope/visit/intent is atomic. Data-only publication cannot revive a canceled native lease. New explicit READ ownership or completed native drag/deceleration may begin a new lease. Route cover, detach, follow/target/inactive, and RN public commands retire old work. Same-value return never revives an old witness. RN remains the only contentOffset writer.
2. Capture uses actual visible glyph fragments or current image geometry nearest the usable viewport center, including a partially visible tall row. It retains a bounded ordered fallback set from the same actual capture. Fallback is used only after authoritative removal; unavailable/ambiguous/recycled content blocks fallback.
3. Exact scope membership proves row removal. Exact current row revision and block manifest prove block removal/replacement. Physical detach without authoritative removal is unavailable. Same logical row can change height without changing the saved interior point.
4. Text uses the supported mounted Paragraph UTF16 query, physical mount owner, actual source and fragment. Unchanged-prefix/suffix edits map only at composed-character boundaries. A changed or ambiguous saved span is unavailable; exact deletion or an empty current paragraph is removed. Reflow with identical text preserves its actual cluster point. No substring guessing or inferred glyph heights.
5. Media binds asset identity and an actual loaded UIImageView. It retains a fractional point in the displayed image rectangle. Placeholder/pending/unsupported geometry is unavailable; authoritative asset replacement is removed. The initial implementation supports actual image surfaces, not arbitrary video/canvas/attachment layouts.
6. Geometry must be finite, axis-aligned, in the same real window, and exposed after ancestor clipping. Partial-width exposure is respected. Selected points must lie in that exposed area. Overflow alone does not imply invalid ancestry.
7. Pure descriptor/text mapping controls execute the production Foundation implementation. Native host/provider controls verify source/API wiring and modeled lifetime separately. They cannot qualify UIKit, actual Fabric mounting, scrolling performance, or presented frames; those require the combined application run.

## Integration prerequisite

Legend's relative READ maintenance must explicitly delegate while this provider owns the native READ lease; active TARGET suppression alone is insufficient. The JS phase/intent declaration must match that handoff. RNSScreen listener `screen:readingVisibilityDidChange:` supplies synchronous cover/appear, with exact sender identity and current `nativeReadingVisible` queried on registration.

## Resident admission refinement

RN installs one resident factory per physical scope/visit. A fresh provisional provider captures before mutation at willMount when READ is not admitted. `beginReadPointLeaseFromResident:(NSString *)intent` requests explicit admission using the exact atomic descriptor intent; RN promotes only that transaction's exact candidate under unchanged native command/gesture generation. Provider `admit()` acquires no geometry; it validates current scope/visit/screen and READ phase, then binds current intent. Active READ retains its own persistent saved points. Routine non-READ metadata updates cannot invalidate a candidate; actual native commands, gestures, scope and visibility changes still can. Missing admission preserves the transaction's preselected legacy owner and must not be reported as interior READ proof. Registry controls require the exact intent to reach the native admission port; native tombstones and queued relative-signal arbitration are validated by the RN seam controls separately.

## Native fixture host acceptance

The explicit ScrollStability entry currently supplies NavigationContainer context but no navigator-created RNSScreen. Its iOS fixture host must use the real enabled ScreenContainer with one enabled Screen at activityState=2. Both retain flex:1 without new safe-area, margin, padding, header or manual layout. The root measurement marker remains inside that screen; scenario resets replace the channel, not the screen owner. No JS callback sets nativeReadingVisible or invokes native appearance. Non-iOS fixture rendering remains its original child tree. Host wiring controls verify these declarations and preserved child lifetime; the next native capture must verify actual RNSScreen appearance and geometry. Missing native screen still rejects provider acquisition.


## Cached rejection diagnostics

`nativeReading.provider` extends the existing RN diagnostic object without changing its fields. Version 1 contains capture/admission attempt counts and the latest cached registration, capture, and admission reason. Capture includes counts observed in the existing bounded walk and rejection counts; an unavailable Paragraph query also records the numeric `TextReadingPointReason` from the installed API. Counts describe work visited before that return, not a fresh complete tree inventory. No text, keys, descriptors, scope/intent tokens, or native object identity is exported.

Reasons distinguish no attached/unique scope, bad current descriptor, invisible or mismatched owner, missing central membership/interior, unexpected Paragraph or transform, unexposed glyph, unavailable capture API, and admission rejection. Not-attempted remains distinct from unavailable. Snapshots are copied; reading the bridge performs no geometry query, tree scan, descriptor parse, admission, or scroll write. The fixed cached state is diagnostic evidence only: it does not repair or retrospectively explain R9b. Actual-body host controls use modeled UIKit/Paragraph responses; the next application capture must identify the real rejection.
