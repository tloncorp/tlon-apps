# Scroller regression history and scenario seeds

This ledger turns repository history into proposed regression scenarios. It is an input to the [situation matrix and acceptance criteria](./scroller-test-matrix.md), not a test report. **Every scenario below is unexecuted in this audit.** Existing tests are pointers to reuse or strengthen, not evidence of current correctness or smoothness.

## Evidence scope

Audited on 2026-09-06 in `db/scroll-stability-fixture`, against commit `0084cc91f64472848a4e6c75da4256e13d642819`. The checkout had pre-existing scroller/diagnostics work; this audit only adds this document.

The repository is not shallow. Searches covered all locally available branches, remote-tracking refs, and tags; 1,079 local/remote branch refs were present. This is **not a claim that every historical bug has been found**. Unfetched/deleted remote refs, private issue discussions, uncommitted work, undocumented bugs, and unrelated fixes with uninformative messages can escape this search. No remote refresh or complete GitHub/Linear issue export was performed.

Search passes, whose counts overlap and must not be added:

- 1,311 commit-message candidates for `scroll|jank|jump|anchor|pagination|keyboard|composer|unread`, including merges, rebases, unrelated backend work, and duplicate patches.
- 425 `Scroller.tsx` history entries with rename following, reaching `packages/ui/src/components/Channel/Scroller.tsx` and the original 2024 `ChatScroll` implementation.
- 227 entries touching the current PostList directory and the two dedicated web scroll specs.
- 193 entries touching retired `ui/src/chat/ChatScroller`, `ui/src/components/VirtualScroller`, and `apps/tlon-web/src/chat/ChatScroller` paths, reaching 2022.
- Additional path/keyword passes through anchor helpers, channel queries, pending-post merging, thread reads, post references, keyboard patches, composer/attachments, native chrome, and the experimental native-list branch.

The ledger contains 86 scenario seeds linked to 109 source commits: 90 in HEAD's ancestry and 19 on other locally reachable refs. It deduplicates by failure mode, not commit subject. Each source link below identifies a commit inspected through its patch or explicit detailed failure report; a source can substantiate several separate scenarios. Proposed acceptance often deliberately exceeds what the historical workaround guaranteed.

Source suffixes are ancestry, not validation:

- **H**: representative commit is an ancestor of the audited HEAD. It may target a retired engine or have been superseded/reverted later; it does not prove the fix is active today.
- **B**: representative commit exists on another locally reachable ref and is not an ancestor of audited HEAD. It is a branch candidate/history seed, not a shipped-fix claim. An equivalent rebased patch may exist under another hash.
- **Retired**: the source implementation no longer drives the current conversation path. Retain the behavioral scenario without reintroducing its old workaround.
- **Prototype**: separate native conversation-list work; historical measurements and failures are not results for the current production scroller.

Family IDs (`ENT`, `NAV`, `GES`, `DAT`, `CNT`, `SND`, `CMP`, `KEY`, `ATT`, `UNR`, `THR`, `OVR`, `LIF`, `GEO`, `RES`, `A11Y`, `WEB`, `RAC`) refer to the main matrix. `REG-*` IDs below are stable proposed executable scenario IDs. Use them in future fixture names, test annotations, and failure artifacts. The main matrix owns numeric tolerances and policy decisions; “stable” below means its frame-by-frame anchor, landing, visibility, and timing criteria, not merely a final screenshot.

The main matrix also expands stateful loading/remount behavior through `STA-*`
and non-chat layouts through `LAY-*`. Apply those variants to the relevant
historical rows, particularly media/loading/consumption regressions REG-063
through REG-067; a synthetic resize alone does not replay their state lifecycle.

## Decisions the history makes unavoidable

The product policies in the [main matrix](./scroller-test-matrix.md#accepted-product-policies)
were accepted by Daniel on 2026-09-06. The obligations below now guide test
implementation; they are not pending approval. Historical behavior is not an
alternative passing contract when it conflicts with the accepted policy.

1. Specify when reader intent beats end-follow, including tiny upward gestures, active momentum, programmatic commands, and a send that arrives after the user moves. The historical threshold changes repeatedly traded one failure for another.
2. Specify selected/unread landing independently for native conversation, web conversation, and fallback grid/detail paths. Current implementations have had different origins and clamping policies; a test must not silently normalize them.
3. Separate loading completion, anchor completion, command completion, and measurement settling. An overlay disappearing or a promise resolving is not proof of correct final position.
4. Measure during transitions. Existing “still visible” assertions can pass despite a flash, two opposite jumps, focus loss, or a long frame between samples.
5. A finite suite cannot establish universal zero jank. It can enforce explicit zero-defect observations for the recorded corpus, seeds, event orderings, devices, refresh rates, and build artifacts, and preserve enough evidence to reproduce every failure.
