# Native correction diagnostics

The R3 `history-cache` recording preserves a qualified 1392 pt reading jump
after content below the reader grows. The installed visible-ID refresh patch
does not resolve that case. Existing raw geometry cannot distinguish the
library's selected visible anchor, an active explicit target, or a preserved
initial target. Record the actual decision before changing those behaviors.

Acceptance for the diagnostic acquisition:

- Observe the same production positioning commands, mutation, and quiet tail.
  Do not write private list state or replace the reader's positioning policy.
- Record the mounted list owner, scope, monotonic time, correction producer,
  selected anchor and target state at the decision and adjustment dispatch.
  Copy primitive values; retain no mutable library objects in exported evidence.
- Enable the dependency observer only for the diagnostic fixture acquisition.
  Bound its records, report overflow, and dispose it with its owning list.
  A missing hook, observer error, changed owner, or overflow prevents causal
  attribution. None of these conditions can make geometry pass.
- For each native JS bridge bracket, retain the existing coherence decision and
  expose its individual predicates: list presence/identity, composer identity,
  required row registrations, data membership, scope, and semantic stability.
  Include before/after membership and semantic commit state to explain failures.
- Preserve every invalid sample and the existing 32 ms acquisition budget.
  Diagnostic timestamps and internal offsets are not native painted-frame proof.
- Verify disabled/enabled observer paths produce the same library behavior,
  snapshot values survive later state mutation, and separate owners cannot mix
  records. Independently replay the original geometric acceptance after capture.

The existing R2 and R3 recordings remain immutable. Any later diagnostic run
has its own source manifest, executable and embedded JavaScript provenance.
